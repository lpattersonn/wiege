## Foundation

- SPEC §3 changed mid-task (shared Supabase database). Wiege's migration history is in wiege.__wiege_migrations, set in drizzle.config.ts (migrations: { schema, table }) and in runMigrations/createTestDb. 0000_init uses CREATE SCHEMA IF NOT EXISTS. 0001_harden_rls enables RLS on all 6 tables plus the history table, and revokes anon/authenticated on schema wiege (guarded by pg_roles). Nothing touches public, drizzle, extensions or roles.
- CLI scripts must run with `tsx --conditions=react-server` because the server modules import 'server-only' (the npm scripts already pass it). They should also `import './load-env'` first, which loads .env files in Next's order. scripts/ingest.ts and scripts/sources.ts should follow the same pattern.
- The exported cached functions in stories.ts work only inside a Next.js server; unstable_cache throws outside one. In scripts, and for fresh (uncached) values in /api/health, use createStoryQueries(getDb()), which also provides getStoryCounts(). listStories returns { stories, nextCursor }, not an array. The ISO date strings are JSON-safe for client islands.
- Ingestion: to lock a run, mark runs that have been 'running' for more than 20 minutes as 'failed', then insert a 'running' row. The partial unique index ingest_runs_single_running_idx makes a second insert fail with 23505, which means return 'skipped'. sources has etag/lastModified columns for conditional GET. The cleanup step should call purgeExpiredRateLimits(). The revalidate.ts stub calls revalidateTag('stories', 'max'); consider { expire: 0 } from the cron route if you need the change visible immediately.
- Literacy: practice-story articles need a source row (sourceId is a foreign key), e.g. id 'wiege-practice'. sources.category must be one of the 4 slugs, but article.category is independent. Use countWords/tokenizeWords from '@/lib/progress/text' in computeWritingStats so word counts match the journal reducer. The Anthropic SDK 0.128 schema transform sends enums only as description hints; zod enforces them when the response is parsed. Run lessonContentProblems()/writingFeedbackProblems() after parsing to check counts, ranges and whole numbers, because the schemas deliberately avoid .int() and length bounds.
- Route handlers: POST /api/feedback should run isSameOriginRequest(request), then clientKey(request.headers), then limitFeedback(hash), but only when Claude will actually be called. On 'ip'/'global' return 429 with a Retry-After header (retryAfterSeconds); on 'unavailable' the client falls back to its heuristic feedback. /api/define should use limitDefine(clientKey(headers)).
- UI: read local records with getOwn()/Object.hasOwn(), never words[w], because a saved word such as 'constructor' is a real key. Word keys are normalizeWordKey(word). useLocal returns null until hydrated, so render a same-size placeholder. Dispatch saveEntry with the prompt's minWords (free writes default to 50, with a 20-word floor). Quiz XP is paid on the first attempt only and the best score is kept. Word-saving XP is capped at 10 XP per day (5 words), and a word earns XP only once ever. Default prefs: gradeBand null, aiFeedback true, textSize 'm', theme 'system'. The stamps have name and hint fields for locked outlines.
- instrumentation.ts: runMigrations() reads process.cwd()/drizzle. On Netlify, include drizzle/** in the function bundle (netlify.toml included_files), or set WIEGE_AUTO_MIGRATE=0 and rely on prebuild. Call getEnv() at boot to fail fast. isServerlessHost() detects Netlify and Vercel.
- Production needs DATABASE_URL (transaction pooler 6543), MIGRATION_DATABASE_URL (session pooler 5432), WIEGE_IP_SALT (at least 16 characters; without it a random per-instance salt is used and an error is logged), CRON_SECRET (at least 16 characters) and WIEGE_SITE_URL. next.config.ts sends HSTS only when NODE_ENV=production.
- The local dev database is running now (port 54329, data in ./data/postgres, log in ./data/postgres.log) and is migrated and seeded with the stubs. `npm run dev` starts it automatically unless DATABASE_URL points at another server.

## Ingestion

- **Literacy owner:** `generateLesson` is called with `{ siblingTitles, timeoutMs }`, where `timeoutMs` is the time left in a budgeted run. `requestStructured` leaves the SDK's default `maxRetries` (2), and the SDK retries timeouts, so a budgeted call can take up to 3× `timeoutMs`. Suggest `maxRetries: 0` whenever `timeoutMs` is set.
- **Foundation owner, env.ts:** `isServerlessHost()` only checks NETLIFY and VERCEL. Netlify only exposes NETLIFY at build time, not inside functions. My code uses `isServerlessRuntime()` in cron.ts, which also checks AWS_LAMBDA_FUNCTION_NAME and LAMBDA_TASK_ROOT. Suggest env.ts do the same.
- **.env.example:** it sets `WIEGE_INGEST_BUDGET_MS=20000` explicitly. An explicit value makes cron-triggered runs budgeted on any host, including self-hosted ones. Suggest leaving it empty with the comment 'default 20000 on Netlify/Vercel, unlimited elsewhere'. Also document `WIEGE_SCHEDULER=0` for developers who don't want a live ingest.
- **Development:** once `next dev` restarts with src/instrumentation.ts, boot migrations run and the scheduler starts. About 30 s after boot it runs a catch-up ingest if the last run is more than 4 h old, which writes real news into the shared dev database (port 54329). Set `WIEGE_SCHEDULER=0` in .env.local to turn it off.
- **Shared dev database:** I ran `npm run sources -- sync` once against it, which upserted the 11 curated source rows (the same thing `db:seed` now does). I wrote no articles or runs there.
- **UI owners:** `FEEDS` in feeds.ts has no server-only import, so /parents can list sources (name, homepage, why) directly.
- **Route groups:** the tag `stories` refreshes every page that reads stories, wherever it lives. If /read/[slug] or /c/[category] move into a route group, update `STORY_PAGE_PATHS` in revalidate.ts to include the group (e.g. `/(app)/read/[slug]`).
- **Netlify:** netlify.toml includes `drizzle/**` in functions so boot migrations can find it. `WIEGE_AUTO_MIGRATE=0` is the simpler option there, because prebuild already migrates. The site needs CRON_SECRET (16+ characters); Netlify provides URL.
- **GitHub Actions:** set repository secrets DATABASE_URL (transaction pooler), ANTHROPIC_API_KEY and CRON_SECRET, and the repository variable WIEGE_SITE_URL. When both the Netlify schedule and GitHub Actions fire at the same slot, one run skips because of the lock.
- **Optional, next.config.ts:** if Turbopack has trouble bundling `linkedom`, `rss-parser` or `@mozilla/readability`, add them to `serverExternalPackages`. I don't expect it: 'canvas', the only optional require, is already in Next's default external list.
- **Ops:** `npm run sources -- list|enable <id>|disable <id>|sync` and `npm run ingest -- [--budget <ms>] [--json]`. /api/health is public and contains no secrets.

## Literacy engine

- UI (reader and landing): call getLandingDemoStory() in a Server Component and pass `content` to the client island. samples.ts pulls in all 12 stories (about 100 KB), so do not import it from client code.
- UI (reader): heuristic vocabulary words are stored in lower case, while Claude and practice words keep the case used in the text, so match vocabulary to the retelling without regard to case and on whole words. Use lessonReadingMinutes(content, band) for the reading-time label.
- UI (practice stories): they are stored with isSample=true, source 'Wiege practice' (id 'wiege-practice', homepage '/about', disabled) and url '/read/<slug>'. Hide 'Read the original at <Source>' when story.isSample and show the 'Practice story' label instead.
- UI (editor chips and feedback): use findUsedVocabulary(text, vocabulary) from '@/lib/literacy/feedback-core' so the chips tick exactly as feedback counts them. heuristicFeedback() also accepts optional minWords, maxWords and promptKind (use 'free' for free writes) for better advice. POST /api/feedback accepts the same optional fields.
- UI (feedback): show heuristicFeedback() immediately. Call /api/feedback only when prefs.aiFeedback is on and the text is more than 6000 characters' worth under the limit. On any response other than 200 (all carry fallback: 'heuristic'), keep the offline feedback; the `message` is written for students. A 422 means the writing is under 5 words.
- Privacy page: AI feedback sends the prompt, the text, the grade band and the story's vocabulary words (plus the optional target length and prompt kind). It is not stored or logged, and only a salted IP hash is kept, in an expiring rate-limit key.
- Env and docs (owner of env.ts and .env.example): ai/client.ts reads ANTHROPIC_AUTH_TOKEN directly from process.env with a local zod check, because env.ts does not declare it. Consider adding it to the env schema and to .env.example.
- Hosting: /api/feedback sets maxDuration = 60 and FEEDBACK_TIMEOUT_MS is 45 s. Netlify synchronous functions default to 10 s (configurable up to 26 s), so either raise the function timeout in netlify.toml or lower FEEDBACK_TIMEOUT_MS in src/lib/literacy/claude.ts. When the call times out, the client shows the offline feedback.
- Hosting: CDN cache keys for /api/define must include the query string. Netlify and Vercel do this by default.
- Ingestion: GenerateLessonOptions.timeoutMs is a hard budget for the whole Claude call. SDK retries are off and the one max_tokens retry runs only if at least 5 s remain; otherwise the offline lesson is used. generateLesson rejects only if the offline lesson is incomplete or fails scanLesson; treat that as 'failed'.
- Ingestion (sources): the practice source has the non-http feedUrl 'wiege:practice' and enabled=false. Make sure the sources CLI, health report and fetcher skip disabled sources and do not assume an http feed URL.
- Prompts: prompts.test.ts pins sha256 hashes of both system prompts so they stay byte-stable for caching. After a deliberate prompt edit, run `npx vitest run src/lib/literacy/prompts.test.ts -u`.
